Financial data terminal for wealth management. Stocks from LongEquity reports + index universes (S&P 500, ACWI), priced from GuruFocus; a second ISIN-keyed "asset" world priced from Yahoo. Momentum backtester, scheduled live portfolios, AIRS model-portfolio analytics.

## Architecture

- **Frontend** Next.js 16 App Router → Vercel (`frontend/`); all components `'use client'`.
- **Backend** FastAPI + `uv` → Railway (`backend/`); `main.py` (~110 lines) is a thin bootstrap, endpoints live in `routers/`, contract in `backend/openapi.json`.
- **DB** Supabase Postgres; migrations in `supabase/migrations/`. **Auth** Supabase Auth (email/password).
- One hosted **prod** project + a **local** Supabase for dev (local is the working dataset; the old hosted dev project is gone).

## Running locally

Prereqs: Docker Desktop, Node+npm, Python+uv.
1. `npx supabase start` → Studio `:54323`, REST `:54321`, DB `:54322`, Mailpit `:54324`.
2. `.env.local` files (gitignored; keys from `npx supabase status`): `backend/.env.local` = `SUPABASE_URL=http://127.0.0.1:54321` + `SUPABASE_SERVICE_KEY`; `frontend/.env.local` = `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_API_URL=http://localhost:8000`, `NEXT_PUBLIC_ALLOWED_EMAILS`.
3. `cd backend && uv run uvicorn main:app --reload --port 8000` · `cd frontend && npm run dev`.

`npx supabase` … `status` · `migration new <name>` · `db diff` · `db push` (→ prod) · `stop` · **`db reset` = ask first** (local data is slow to refill; migrate non-destructively).
**Env precedence**: backend loads `.env` then `.env.local` with `override=True` (absent on Railway). Frontend = Next convention; Vercel uses dashboard vars. Always `uv run python`, never bare `python`.

## Backend map → [`docs/backend.md`](docs/backend.md)

- **Top level**: `deps.py` (Supabase client factory + env; routers import from here, never `main`) · `scheduler.py` · `portfolio.py` (AIRS Excel) · `airs_scanner.py` (Playwright AirSPMS) · `fx_rates.py` (ECB/Yahoo → `fx_rate`) · `common/pg.py` (direct-Postgres `COPY` transport, re-exported by `momentum/data/_pg.py`).
- **`timeseries/`** — ONE interface for per-entity series. `load_series(ids, series, start, end)` · `to_panel()` (factorize+scatter, 6× `pivot_table`). Series keyed **vendor + entity domain**: `gf.close|gf.volume` (`company_id`, `metric_data`) vs `yf.close|yf.volume` (`analysis_id`, `asset_price`). `resolve()` **refuses to mix domains** (disjoint id spaces; only 2,065/16,150 `asset_execution` rows bridge by ISIN) and refuses to fuse two EAV rows into one query. **Transport is the speed**: 1,080 ms via PostgREST paging vs 89 ms via one `COPY`.
- **`signal_engine/`** — ONE declaration of all 19 signals. `key` is cadence-namespaced (`daily.mom_12_1`, `me.mom_12_1`); `name` is the legacy public string saved configs/`/signal-lab` use, and **names are not unique across cadences on purpose**. `daily.py` owns as-of discipline (strict `<`, `MIN_BARS=20`, `MAX_STALENESS_DAYS=30`). ⚠ `registry.PARITY`: `mom_12_1` is the same signal across cadences (ρ 0.996) but **`vol_trend_3m` is NOT** (ρ 0.58, 29% sign flips) — never merge them, never render a signal without its cadence.
- **`routers/`** flat per domain + sub-packages `momentum/`, `universe/`, `index_universe/`. **`_auth_middleware.py` is the API auth gate**: every `/api/*` needs a valid Supabase JWT, role-gated (admins all; non-admins only the reads behind their pages + two allow-listed momentum detail routes, each re-authorized via the owning strategy's `user_visible`, + **every /management-dashboard REFRESH** — `_USER_REFRESH_PATHS`/`_PATTERNS`, 2026-08-19: the AIRS scrapes, the index rebuilds, the fundamentals fills and the `/api/jobs` transport that carries them. ⚠ The line is **refresh vs. mutate** — a user makes that page's figures current, never changes what it says, so its deletes, renames and Class/ISIN/Link pins stay admin-only, and every allowed path is written out in full because both tiers sit one segment apart under the same prefix); anonymous → 401. Public: `/api/health`, `/api/hello`, `*/cron` (`X-Cron-Secret`). Role + admin "view as user" resolve through **one** helper `routers/_authz.py::is_admin_request` (honors `X-View-As`). **⚠ All frontend calls must attach the JWT — use `lib/apiFetch.ts`, and `runSSE` for SSE; never `EventSource` (can't send headers).**
- **`ingest/`** LongEquity+GuruFocus: acquire → flatten → extend_primary → transformation → load_into_supabase, plus `resolve_tickers` (OpenFIGI), `prices`, `staleness`, `api_usage`, `prune_companies`, `dedupe`, `delisting`. **`ingest/phases/`** = the scheduled pipeline, one unit-testable module per phase (`runlog`, `acquisition`, `templates`, `prune`, `prices`, `momentum`, `pipeline` = the orchestrators). `routers/ingest_runs.py` is HTTP only.
- **`momentum/`** `data.py` (bulk loaders, FX, `IN_CHUNK_SIZE`=200) · `signals.py` (5 price + 2 volume, strict `<`, 30-day staleness drop) · `scoring.py` (per-category 0-100 min-max → `momentum_score`) · `backtest.py` (`run_backtest`, `run_multi_trial_backtest`, `run_current_portfolio`) · `portfolio_math.py`.

Re-baseline deliberately via `scripts/capture_golden_rebalance.py`, never to green a red test. ⚠ Uncovered: routers, admin paths, prune/template/momentum orchestrators, `merge_existing_duplicates` — close with `_fake_supabase.py`, not a new stack harness.

## Conventions & traps → [`docs/conventions.md`](docs/conventions.md)

Each line is a rule + its measured incident. Read the doc before working in the area.

**Data access**
- ⚠⚠ **PostgREST truncates SILENTLY** — 1,000 rows on cloud, 10,000 locally, so *the same code gives different answers per environment*. Every large read MUST page (`.range()`), advance by **what came back** (`off += len(rows)`, break on an empty page — `len(rows) < page` assumes the server cap ≥ page size, the assumption that failed), and prefer one `COPY` where available. Unpaged FX read: TWD came back as 20 rows from 2026-05-27 (real history 2014) → Taiwan Semi (5% weight, 6,606 bars) **silently left its portfolio** and the return renormalised over the rest; 36.64% local vs **44.14% prod**, 49 of 56 models wrong, no empty cell anywhere.
- ⚠⚠ **Page on a UNIQUE sort key** — shipped twice (FX rates; `_page_metrics` ordering on `target_date` alone while a company files ~110 codes per date, so *every* boundary fell in a tie: ASML/Alphabet/Amazon each silently lost 2018). Postgres promises nothing about tied rows across separate LIMIT/OFFSET queries. Prove it with `tests/_fake_supabase.py`'s **`unstable_ties=`** and `max_rows=`; a stable local server hides the bug completely.
- ⚠⚠ **Never OFFSET-page an expensive view through PostgREST** — every page re-materializes the whole view and throws away the rows before its offset, so per-page cost grows with the offset while the budget stays at the **8s `statement_timeout` on the `authenticator` role** (which `service_role` inherits, having no override). That took `/asset-pipeline` down: page 1 in 1.3s, everything past offset ~8,000 → **57014**, so `/grid` raised and the page had nothing to render. Cause was a correlated `LEFT JOIN LATERAL` over the `universe_asset_membership` **view** re-deriving the ISIN bridge per row (8,055 executions, seq-scanning `company` each time) — `asset_grid` at 10.3s. Fixed by pre-aggregating that join (migration `20260817010000`: 10.3s → 0.80s, output hash-identical) and by reading the relation in ONE `COPY` (`common/pg.py::load_table_via_copy`: 17 pages 12.68s → 0.80s, rows byte-identical, and one MVCC snapshot instead of 17). ⚠ **Benchmark a wide view by reading its ROWS, never `count(*)`** — a `LEFT JOIN LATERAL` cannot change the row count, so Postgres elides it: `count(*)` was **0.03s** against **10.33s** to project the same rows, which is how the migration that introduced this recorded "28ms — it costs nothing".
- Batch `.in_()` in `IN_CHUNK_SIZE` (=200, `deps.py`) chunks — Cloudflare 502 guard. (`ingest/prune_companies.py` still hardcodes `_IN_CHUNK=50` — drift worth unifying.)
- **PostgREST runs over HTTP/1.1** (`deps.py::_build` swaps postgrest-py's hardcoded `http2=True` session): Supabase's Cloudflare gateway sends an HTTP/2 GOAWAY once requests-per-connection is hit → `RemoteProtocolError` mid-batch. Complementary: `ingest/prices.py::prime_db_max_dates` precomputes both metrics' latest dates in ONE grouped COPY instead of per-company reads.
- Backend wraps blocking Supabase calls in `asyncio.to_thread()`; SSE for long ops, with `: keepalive` comments before long work.
- **No HTTP cache on UI-mutable lists** — use `CACHE_NONE`, not `CACHE_PIPELINE`, or stale cache defeats frontend invalidation.

**Money, returns, identity**
- ⚠ **EUR is the return basis everywhere** (incl. the FX leg). The price-update re-pricer once computed off local prices and the header disagreed with the card by ~FX%.
- ⚠ **Held-basket return has ONE source of truth** (`momentum/portfolio_math.py`): `holding_eur_return_pct` → `portfolio_eur_return_pct`; writers call these, **every consumer READS `period_return_pct`/`forward_return_pct` and never recomputes** (header MTD, Current-portfolio card, run history). When adding any return surface, read the stored value.
- **Cash sleeve** = `scheduled_strategy.config["cash_pct"]`; `apply_cash_allocation` strips existing cash, renormalizes to 1, scales by `(1-cash)`, appends `company_id=0` flat-1.0-EUR cash (idempotent). It also scales all *backtested* stats (`_scale_curve_returns`), and **Sharpe/Sortino are cash-invariant** by construction. Admin-only `PATCH …/{id}/cash`.
- ⚠ **`GBp` is PENCE, not a currency code** — 343 `asset_execution` rows, and `fx_rate` has only `GBP`. Missing rate ⇒ every caller reads "unpriceable" (Judges Scientific, 5,930 bars, vanished from 13 portfolios); forget the *divisor* instead and £46.75 prices at £4,675. Resolve the minor unit through **`asset_pipeline.fx.SUBUNIT`** and scale the **rate** (`eur = pence / (100 × gbp_rate)`), and make FX loaders ask for the MAJOR code too. `ZAc`/`ILA` likewise.
- ⚠ **Two companies are the same security iff they share an ISIN.** ISIN dedupe (`dedupe_by_isin`) keeps the Leonteq/USA/EU listing; the DUPE badge is ISIN-based (name-matching false-flags GOOG/GOOGL). A **NAME DUPE** badge/merge covers the gap where ≥1 side has no ISIN, folding only in a bucket with exactly one ISIN-bearing row and only for trailing corporate-suffix differences (`Celestica`→`Celestica Inc` yes; `Siemens Ltd`→`Siemens AG` **no**). Same rule in `company/nameDupe.ts`.
- **Cross-ISIN dupes** (one issuer, two ISINs — ADR vs home line) are handled only by a `company_override` row (`alias`/`exclude`/`set_isin`), applied every ingest by `apply_company_overrides` (moves memberships + cap, **drops the secondary's prices**). ⚠ The by-hand helpers (`merge_companies`, `record_isin_alias`, `add_exclusion`, `set_company_isin`) were **deleted 2026-08-03** — insert the override row directly.
- ⚠ **Never compare company names with a raw `_name_score >= _NAME_MATCH` floor — use `asset_pipeline.resolve.same_company()`** (strips corporate forms). `token_set_ratio("NVIDIA Corporation","NVIDIA CORP")` = 75.9 < 80, which once moved NVDA to **Stuttgart** (€1.6M/day vs Nasdaq's €28,076M). Detect wrong listings by **median daily traded value ÷ market cap** (`<1e-5`), never an exchange map (Vienna≠Prague) and never "ISIN country ≠ listing country" (flags every deliberate ADR mapping). ⚠ A **missing** market cap is a signal, not a skip — a dead listing is exactly what reports no cap (Brown & Brown on BTW.DE, €7,836/day, zero bars, vs NYSE €154M). ⚠⚠ And that cap check was, by accident, the only fence keeping **funds** out of a name-based resolver (WisdomTree Coffee → **Luckin Coffee**, `same_company` exactly 80.0) — the fence is now the explicit allowlist `_NAME_RESOLVABLE_TYPES`, and no `openfigi_name` ⇒ refused. *The protection was incidental, therefore invisible, therefore removable without anyone noticing.*
- ⚠ `token_set_ratio` scores a **subset** as 100 (`eur` ⊂ `Shell PLC EUR` → 20 false portfolio links) — use `token_sort_ratio`; and a stemmer that removes the shared product word ("TopSelectie") merges two different product lines, so gate on the product line **before** stripping.

**Vendors**
- ⚠ **The GuruFocus legacy API never 404s** — `stock/{sym}/<anything>` returns 200 + a 46-point all-zero series, so `news`/`splits`/`profile`/`analyst_estimates`… all *look* real. Always probe with a canary sub-path; the true catalogue is [`docs/gurufocus_api.md`](docs/gurufocus_api.md) + `backend/gurufocus_api.json` (`scripts/gurufocus_catalog.py`, responses cached in `.gurufocus_cache/`). Undocumented but load-bearing: `isin/{ISIN}`, `cusip/{CUSIP}`, `exchange_list`. `dividend` (per share) ≠ `dividends` (cash flow, $M, negative).
- **Subscription** covers USA + continental Europe + Asia/Middle East, **except India (NSE/`BOM`), UK (LSE), Ireland (DUB)**; Russia/Africa/LatAm/AU-NZ out too (`FEASIBLE_GF_EXCHANGES`). US OTC Pink (`OTCPK`) **is** covered, so foreign names with a US OTC line are fixable. Out-of-coverage rows show **UNSUBSCRIBED**.
- ⚠ **Yahoo answers an overloaded caller with an EMPTY list, not a 429** — a candidate set missing the real listing hands the win to a thin foreign line. Hence: **never re-resolve an existing asset row** (`/store` 409s; Alphabet re-resolved to `GOOA.VI` Vienna, **75,000× thinner**), and the price refresh stands down while the ingest **worker** is live (`queue.is_worker_active()` — read the heartbeat, not the backlog: 9,945 rows sat pending from a week earlier).
- ⚠ Yahoo's `region` field is always `"US"` (request locale) — listing country comes from the exchange/suffix, domicile from `assetProfile.country`; no region field exists anywhere.
- ⚠ Yahoo speaks **two sector vocabularies** (`Materials`/`Basic Materials`, `Financials`/`Financial Services`) — unmerged they are two buckets and Brinson reports a phantom allocation bet. Canonicalize in `_airs_portfolio_analysis._sector`.
- ⚠ **Region is the issuer's, currency is the company's — never our venue's.** `asset_grid.msci_region` falls back to the *listing* country, so US megacaps priced on thin German lines (`LLY.SG`, `CHV.DU`, `IBM.HM`) made the S&P read 7.2% European; by listing currency it read 91% USD vs 98% by `market_cap_currency`. Go domicile → ISIN country prefix → `Unclassified`.

**Prices**
- ⚠⚠ **Our stored closes are NOT split-adjusted and cannot self-heal** — ingest only fetches dates *newer* than stored max, so a vendor's retroactive split rewrite is never re-read (KLA 1929→211, CrowdStrike 763→193, DuPont 48→140: 3 of 493 S&P names in 2026). It hits a cap-weighted index **twice in the same direction** (the start weight is backed out through the same broken price). `_split_adjust` corrects only against an explicit whitelist of real ratios — "any small rational" would "fix" a genuine −45% crash — and every adjustment is surfaced, never silent. **This is a patch: the same rows feed the momentum signals.**
- ⚠ `metric_data` is append-only in `recorded_at`, **not `target_date`** (GuruFocus publishes late closes with their true earlier date), so a past snapshot can never be reproduced from the live DB.
- **Momentum cutoff is strict `<`** — never train on the bar we trade; >30-day-stale tickers are dropped. A non-Monday `rebalance_weekday` decides on the prior trading day's close and enters at the rebalance close.
- **Price-status markers** (`company.*_at`, all excluded from `/api/data/price-coverage`): `delisted_at` (auto, >15 trading days behind the global latest close) · `out_of_scope_at` · `illiquid_at` (manual, still priced). Price/volume cutoff `1998-01-01`. Raw GuruFocus JSON cached in Storage bucket `gurufocus-raw`; transient Storage/upsert errors retry 3× (`_retry_transient`).
- ⚠ **`fx_rate` history is thin and `load_fx_rates` hides it** — `.ffill().bfill()` extends the earliest stored rate backwards to any `start_date`, so a window starting before a currency's stored minimum converts that whole stretch at one wrong rate: a plausible number, never a blank. **FIXED 2026-08-18** — `sync_fx_rates_to_db` now widens at BOTH ends (it read the stored max and fetched from max+1, and its "already covered forward" short-circuit `return`ed from the function, so the head gap was unreachable on exactly the currencies that were current). The 16:30 `fx_sync` already asks from 2000-01-01, so it repairs every currency's head on its next run. `routers/_asset_dividends.py::_backfill_fx_history` now DELEGATES rather than keeping a second widener. Pinned by `tests/test_fx_backwards_gap.py`.
- Company deletion cascades: `metric_data` + `portfolio_weight` first.

**Frontend behavior**
- ⚠⚠ **A failed email link must never reach `/set-password`** (2026-08-19). `/auth/confirm` discarded the result of `exchangeCodeForSession`/`verifyOtp` and redirected to the password form regardless — so every failure produced a working-looking form and, only after the person chose a password, `updateUser` failing with **"Auth session missing"**: the symptom, at the screen where the cause cannot be fixed. Two causes, both production-only, and they need **different** fixes: (1) ⚠ **PKCE is per-browser** — `?code=` can only be exchanged by the browser that requested the link, so asking on a laptop and opening the mail on a phone cannot work, and locally there is only ever one browser. Fixed by the email templates (`supabase/templates/*.html`, mirrored in the **prod dashboard**) using `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=signup`, which carries no per-browser state. (2) ⚠⚠ **A single-use token is spent by ANYTHING that fetches its URL**, and corporate mail scanners fetch every link before the recipient sees it → "link already used". ⚠ **Changing the template does NOT fix this** — `/auth/v1/verify` and our own `/auth/confirm` are both plain GETs, so it moves *who* spends the token, not *whether* a scanner can. Fixed by making `/auth/confirm` a **page with a button** (`page.tsx`, not `route.ts`): the token is read from the URL and nothing happens until the press, so a scanner's GET spends nothing. ⚠ `detectSessionInUrl: false` on that page's client is load-bearing — the default processes `?code=` on load and hands the protection back. Also: `error*` params are checked **before** looking for a code (a rejected token arrives with neither `code` nor `token_hash`, so an "empty query" is a failure, not a no-op), every result is checked, the session is confirmed with `getUser()`, failures get an actionable sentence (`lib/authError.ts`), and `/set-password` refuses to render a form without a session. ⚠ **`confirmation` is the template signup uses** — `signInWithOtp({shouldCreateUser:true})` sends "Confirm signup" to a new address and "Magic Link" only to an existing one.
- **Live dashboards use SSE, not polling** (`routers/_sse_stream.py` re-emits a topic only when it changes; frames are `{topic,payload}` inside `data:` because `runSSE` parses only `data:` lines). Consumers: `lib/hooks/useEventStream.ts` (closes when the tab hides, backoff, `failed` after N) + `lib/watchRun.ts`. **Every migrated surface keeps its `usePollingFetch` fallback**, enabled only on `failed`. Idle `/schedule` now makes zero requests.
- **The Fundamental reads are cached in memory in `apiFetch`** (`lib/readCache.ts`, 10-min TTL, 32 MB, oldest-first). Three rules: (1) ⚠ an **allowlist** of paths, never "every GET" — half this app is a live dashboard and a cached run status shows a finished job as running; (2) ⚠ any successful write drops the whole cache **and that rule lives in `apiFetch`**, not at the ~15 refresh buttons — except writes that only *start* a job, which call `invalidateReadCache` on completion; (3) ⚠ the read-POSTs (`fundamental-blend-metrics/stream`, `/api/airs/basket/analysis`) are exempt, and `blendMetrics` memoises its result against the cache generation (an SSE body can't be replayed).
- ⚠⚠ **A response cache does NOT make a big payload cheap — the Long Equity benchmark line was 13.21 MB per selection** (2026-08-19, `backend/scripts/profile_longequity_bench.py`). Picking ACWI fires 12 requests, each carrying one row per constituent (1,514, vs AEX's 22 — that ratio *is* the complaint). `_blend_cache` already cached them, but it cached the **payload**, so every load still shipped 13 MB and re-ran `jsonable_encoder`+`dumps` (137 ms × 12) to rebuild identical bytes. Three fixes: `cached_blend` now caches the **gzipped body** and honours `Accept-Encoding` (→ 4.85 MB, a hit is a memcpy); `market_cap_by_period` — the same cap table on every row of all ten card responses, **29.9%** of each — moved to one `/universe-period-caps` that `useBenchInputs` splices back (→ 9.34 MB decoded, **3.16 MB** wire); caps 24→84 with the grid in its own `_grid_cache` (24 could not hold ONE screen's working set) and TTL 30min→6h. ⚠ In the splice, `{}` and *absent* are different answers — `weightAt` reads `{}` as "out of that period's average" and absent as "flat `weight_pct`", and both still draw a line. ⚠ `_blend_prewarm` rebuilds ACWI/SP500/AEX in the background — **on startup AND off `invalidate()`** (debounced 90s, serial — ~18s for ACWI because `cached_metric_reads` already shares the reads — stands off `_PIPELINE_LOCK`, armed only by `main.py`, `BLEND_PREWARM=` disables). ⚠⚠ **The startup pass was missing at first and that made the whole file a no-op on a fresh box**: `arm()` started a thread whose first act is `_wake.wait()`, and only a fundamentals WRITE ever set that event — so every Railway deploy left the cache cold and the first reader paid it all (ACWI: 4.4s for the growth blend alone, ~20s for the tab's fan-out). `arm()` now calls `notify()`. Verified: fresh process, no `invalidate()` anywhere → 12 entries in ~20s → first EPS blend **0.0 ms**.
- ⚠⚠ **"CAGR" has exactly one definition and it is point-to-point** — a fitted-exponential slope on the card vs endpoints in the table read 29.7% and 30.1% on the same book. Both now go through `portfolios/lineCagr.ts` (`endpointCagr` / `lineCagr`). The fit is still drawn: it answers *how steady* (R²), the CAGR answers *what the rate was*, so the trend line sitting off the two points **is** what R² measures. Consequence: the card refuses (—) on a non-positive endpoint, and both tiles state their window.
- ⚠⚠ **A metric key is a registry lookup; an unknown one is REFUSED, never defaulted to revenue** — `_metric_codes` used `.get(metric, …["revenue"])`, so `metric=fcf_per_share` (the key is **`fcf_ps`**) returned the book's *revenue* growth under an FCF label: +19.0% vs the card's +28.0%, nothing errored, no empty cell, and the tab's own footnote offered a credible wrong explanation. **At high R² fit-vs-endpoint is worth ~0.5pp — a large gap means the two sides are reading different series.** Now raises → 422 naming the valid keys. ⚠ These keys are plain `.tsx` string literals with no build-time check.
- ⚠⚠ **The AIRS freshness badge measures AIRS's valuation date, not our copy** — 32 of 40 rows amber and *not clearable by the action the tooltip named* (`_vermogen_most_recent` already walks back to the newest available valuation). Pair `as_of` with **`fetched_at`** via `lib/snapshotAge.ts::lagOwner` → `side:'source'|'ours'`, returning **null** rather than guessing when `fetchedAt` is absent, on **one** threshold (≥2 trading days) for both sides. Same class of bug in prose: `format_run_message`'s counts are all about OUR COPY, so it now carries the newest AIRS valuation date in the same sentence (omitted when the run read nothing).
- Error detail → `console.warn` the full diagnostic, one short line in the UI. A message `kind` is a **COLOUR, never a story**. Never use native browser dialogs — use `frontend/lib/dialog.ts`. Surface progress on long commands (no silent multi-minute waits); a long job's toast must emit a first line *before* any work and relay per-step lines (line only, never a bogus `0/0` position).
- AIRS *portfolio* data (the Excel path) is parsed server-side and cached client-side in localStorage — no DB.

**Current-picks identity** — `_strategy_hash(req)` = 16-char SHA-256 of signal/category weights + `top_n_sectors`/`top_n_per_sector`/`max_companies` + universe label + `index_universe` + `selection_mode`. The **date range is excluded** so the sliding "this month" view caches across date-only changes; `current_picks_day` never backfills closed months.

## Deployment + scheduling → [`docs/scheduler.md`](docs/scheduler.md)

Push to `main` → Vercel (frontend) + Railway (backend, long SSE fine) auto-deploy; DB Supabase. All free tier.

`backend/scheduler.py` runs in-process APScheduler. The pipeline is **three ops**, serialized by a module-level `_PIPELINE_LOCK` in `ingest/phases/pipeline.py`, each its own `ingest_run` + `job_name`, each with a /schedule "Run now":
- **`price_update`** — held companies only (union of enabled strategies' latest holdings) → prices → **held ETF benchmarks** → momentum price-update. Re-prices open positions in EUR. Schedules a one-shot **+3h retry** when a held active name lags the *global* freshest close (anchored to the global latest, not the calendar, so "today's close isn't out yet" and a full vendor outage don't false-trigger), max 3/UTC-day.
- **`rebalance`** — due strategies only: plan → templates (only their universes) → dedupe (gated on a template rebuild) → prices → momentum rebalance. No-op when nothing is due.
- **`full_price_refresh`** — month-end, EVERY company most-stale-first, **bounded by the per-region GuruFocus quota** (a region at ≤0 skips its remainder, never errors against an exhausted quota).

Ticks: **05:00 UTC** daily = price_update then rebalance sequentially (05:00 not 02:00 so European EOD closes have published) · **12:00 UTC** daily gates the month-end refresh to the last `MONTH_END_WINDOW_DAYS`+1 days *and* "no successful full run since the window opened", so a missed day retries the next · **06:00** `asset_price_refresh`, the Yahoo twin of the 05:00 GuruFocus update (fetches **the gap** via `store.extend_series`; measures staleness against **the freshest close we hold**; stands down while the ingest worker is live; also fires on startup because a daily tick can't repair the past; logs at **WARNING** when it finds work, since uvicorn leaves root at WARNING) · **11:00 UTC** `job_watchdog` re-runs any job the /schedule page reports `overdue` or `interrupted` (max 2/job/UTC-day; ⚠ never `missing` — that means the schedule itself is broken and healing it would hide that — nor `error`/`unknown`). Six hours after the 05:00 pipeline, so a run has certainly finished or died, and still on the right side of the European EOD publication 05:00 was chosen for · **16:30 Mon-Fri** `fx_sync` for all fetchable currencies (the daily pipeline only syncs *held* currencies) · **05:00 Amsterdam** `airs_model_prices` reprices every PAIRED AIRS model portfolio (`refresh_many(halves=("model",))` — composition → instruments → FX → prices → recompute). ⚠ It deliberately does NOT scrape the accounts: `airs_vermogen_refresh` (09:30 Amsterdam, Mon-Fri) owns that, and 05:00 is documented as too early for it — a forcing account pass before AIRS has valued the books stores YESTERDAY's valuation and nothing re-reads it until tomorrow. Amsterdam-local, unlike the pipeline's 05:00 **UTC**, because this one is about a working morning rather than a market close. Startup `_maybe_kickstart_smart` catches up if a strategy is due or held prices are stale (held only, deliberately not a full reprice). Railway Cron still fires `POST /api/momentum/current-picks/cron` at 02:00 UTC Monday.
⚠ Single-instance assumption — `_PIPELINE_LOCK` is in-process; set `DISABLE_SCHEDULER=1` on all but one replica (also the pause switch). ⚠ A restart at exactly 05:00 drops that tick (startup kickstart covers it). ⚠ Editing backend files under `--reload` kills an in-flight pipeline and leaves a zombie `ingest_run` blocking bootstrap for up to 1h.
**Dropped deliberately**: template-universe *maintenance* — universes no enabled strategy uses (ACWI, LongEquity) go stale until a manual full refresh. That fixed a snapshot-fed template re-pricing all 401 companies on every tick.
